# Отчет по Заданию 1: Исследование моделей и инфраструктуры

## 1. Сравнение LLM-моделей

Для реализации RAG-бота были рассмотрены три варианта. Учитывая ограничения инфраструктуры (ноутбук с Linux, отсутствие мощного GPU) и локацию (РФ), выбор стоял между локальным запуском (через Ollama) и доступными облачными API.

| Характеристика | Local LLM (Llama-3-8B via Ollama/GGUF) | YandexGPT Pro (Cloud) | OpenAI GPT-4o (Cloud) |
| :--- | :--- | :--- | :--- |
| **Качество ответов** | Среднее/Высокое. Хорошо понимает контекст, но возможны галлюцинации на специфичных терминах. | Высокое. Отлично работает с русским языком и контекстом. | Этлонное. Лучшее понимание инструкций. |
| **Скорость** | Зависит от CPU/RAM. На i7/32GB RAM ожидается ~5-10 токенов/сек. Приемлемо для dev-режима. | Высокая (API). Зависит только от сети. | Высокая, но возможны задержки из-за VPN/Proxy. |
| **Стоимость** | **0₽** (используются ресурсы локальной машины). | Платно (по токенам), но недорого для RAG-задач. Есть гранты/Free tier. | Дорого + сложности с оплатой зарубежными картами. |
| **Приватность** | **Полная**. Данные не покидают периметр компании. | Данные уходят в облако Яндекса (требуется проверка NDA). | Данные уходят в США. Неприемлемо для конфиденциальных документов. |
| **Deployment** | Docker Container с Ollama. Требует ~8GB RAM. | Простое подключение библиотеки (SDK/LangChain). | Требует настройки VPN-шлюзов и ротации ключей. |

**Решение:** Используем **гибридный подход**.
*   Для разработки и тестов: **Local LLM (Llama-3 через Ollama)**. Это бесплатно и автономно.
*   Для продакшена (потенциально): **YandexGPT** (из-за лучшего качества русского языка и стабильности).

## 2. Сравнение моделей эмбеддингов

Эмбеддинги — это "фундамент" поиска. Нам нужна модель, которая хорошо понимает семантическую близость в *русском* языке.

| Модель | Тип | Особенности |
| :--- | :--- | :--- |
| **sentence-transformers/all-MiniLM-L6-v2** | Локальная (HuggingFace) | Очень быстрая, легкая, но лучше работает с английским. Для русского качество среднее. |
| **DeepPavlov/rubert-base-cased-sentence** | Локальная (HuggingFace) | Специализирована на русском. Тяжелее, чем MiniLM, но точнее ищет по смыслу. |
| **text-embedding-ada-002 (OpenAI)** | Облачная | Платная, требует VPN. Качество хорошее, но избыточно для MVP. |

**Решение:** Используем локальную модель **`intfloat/multilingual-e5-large`** или **`DeepPavlov`**. Они бесплатны, работают на CPU и показывают отличные результаты на бенчмарках (MTEB) для русского языка. Это избавит нас от лишних сетевых вызовов при поиске.

## 3. Сравнение векторных баз данных

| База | Тип | Плюсы | Минусы |
| :--- | :--- | :--- | :--- |
| **FAISS** (Facebook AI Similarity Search) | Библиотека | Экстремально быстрая. Работает локально (in-memory). Простая интеграция. | Не является полноценной БД (нет CRUD в привычном смысле, сложно масштабировать репликацию). Хранит индекс в RAM. |
| **ChromaDB** | Векторная БД | Open Source, persistence (хранит на диске), удобный API. Популярна в LangChain. | Чуть сложнее в настройке, чем "голый" FAISS. |
| **pgvector** (PostgreSQL) | Расширение | Использует существующую инфраструктуру Postgres. ACID, привычные SQL-запросы. | Требует настройки Postgres. Менее производительна на *огромных* объемах, чем FAISS, но для корпоративной базы знаний идеальна. |

**Решение:** Для MVP выбираем **FAISS**.
*   Почему: Максимальная простота запуска (просто `pip install`). Нам не нужно поднимать отдельный контейнер с БД для 18 000 документов.
*   *Note:* В реальном продакшене (учитывая стек QuantumForge с Postgres) мы бы мигрировали на **pgvector**.

## 4. Рекомендуемая конфигурация сервера

Для развертывания RAG-бота (контейнер с приложением + FAISS индекс + локальная LLM):

*   **CPU:** Минимум 4 ядра (рекомендуется 8). Inference на CPU требует параллелизма.
*   **RAM:**
    *   OS + App: ~2 GB
    *   Vector Index (FAISS): ~1-2 GB (для 20-50к документов)
    *   LLM (Quantized 4-bit): ~6-8 GB
    *   **Итого:** Минимум **16 GB**, рекомендуется **32 GB**.
*   **GPU:** Не обязательно для инференса квантованных моделей, но желательно (NVIDIA T4 / L4) для ускорения ответов (снижение задержки с 5-10 сек до 0.5 сек).
*   **Disk:** 50 GB SSD (модели весят 5-10 GB + индексы + логи).
